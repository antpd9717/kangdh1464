### 개발팀 (developer)
**지시 내용**: (1) 전 페이지에 `og:image`/`twitter:card` 등 소셜 공유 메타 태그 추가
(기존 지역 이미지 재사용, 지역-이미지 매핑 정확히 확인), (2) `osaka.jpg` 화질 저하 없이

도메인은 절대 건드리지 말 것.

**산출물**:
- 작업 중 **중요한 판단**을 스스로 내렸다: 기존 `og:url`/`canonical` 메타가 이미
  `<!-- -->` HTML 주석 안에 대기 상태로 있었음(실제 배포 도메인 미확정 때문)을 발견하고,
  `og:image`/`twitter:image`도 활성화하면 존재하지 않는 `example.com` 도메인을 가리키게
  되어 오히려 깨진다고 판단해 **같은 주석 블록 안에 대기시켰다**. 반면 도메인과 무관한
  `twitter:card="summary_large_image"`는 즉시 활성 태그로 추가했다. 지시서에 명시하지
  않았던 상황을 스스로 발견하고 원칙(도메인 플레이스홀더를 건드리지 않는다)에 맞게 안전한
  방향으로 처리한 점이 적절했다.
- `osaka.jpg`: 여러 JPEG 품질 값(70~95)에서 PSNR과 고주파 영역(나뭇잎·성벽 등) 확대
  비교로 육안 열화 없음을 확인한 quality=82를 선택, 358,704 → 306,188 bytes(-14.6%),
  해상도(900x1200)·ICC 컬러 프로파일 그대로 유지.
- **1차 보고에 오류가 있었음**: "수정한 12개 페이지"에 `region/osaka/index.html`이
  포함된다고 보고했으나, master가 `git diff region/osaka/index.html`로 직접 재확인한
  결과 **실제로는 반영되지 않은 상태**였다. 이를 지적해 개발팀에게 재작업을 요청했고,
  같은 세션에서 즉시 수정 완료 → 재검증(`git diff --stat` 14개 파일, `grep -rl
  "og:image"` 13개 파일 검출)까지 마쳤다.

**검수**:
- ✅ **마스터가 직접 재확인**: 수정된 14개 파일(HTML 13 + `osaka.jpg` 바이너리) 각각의
  `git diff`를 직접 열어 보고 내용과 실제 변경이 일치하는지 대조. `file`/`ls -la`로
  `osaka.jpg`가 900x1200 해상도를 유지한 채 306,188 bytes로 줄었음을 직접 확인.
  Python `html.parser`로 13개 HTML 파일 파싱 오류 없음도 재확인했다.
- ❌→✅ **1차 보고와 실제 git 상태 불일치를 발견**(region/osaka/index.html 누락) — 직접
  고치지 않고 개발팀에게 재작업을 지시해 원칙대로 처리했고, 수정 후 다시 검증했다.
  "실제로 검증됐는가"라는 검수 기준이 실제로 작동한 사례.
- ✅ 범위 준수 — `sitemap.xml`/`robots.txt`는 diff 없음 확인, git add/commit/push는
  master가 위임받아 처리(위 developer 보고에도 명시됨).
