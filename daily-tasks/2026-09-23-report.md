## 1. 착수 전 저장소 상태 점검

- 니치(주제)는 계속 확정 상태(`README.md`, `planning/content-plan.md`): 일본 지역별
  "가볼만한 곳 + 맛집" 여행 정보 사이트. 오늘 세션에서 니치 재정의는 없었다.
- 발행 글은 여전히 3편(오사카 조식, 나오시마 당일치기, 우레시노 온천), 지역 허브 6개
  그대로다. 다음 콘텐츠(가나자와) 본문 작성은 실제 스팟 리서치(WebSearch)가 필요한
  기획팀(planner) 영역이라 오늘 지시 대상(개발/디자인/CS)에서 제외했다(오늘 사용자
  지시 범위가 CS·디자인·개발 세 팀이었음).
- git 상태는 정상(`main`이 `origin/main`과 일치, 로컬 이슈 없음).
- 지난 20일간 스킵 링크, 색상 대비(WCAG AA), prefers-reduced-motion, schema.org
  JSON-LD(Article/WebPage/CollectionPage), alt 텍스트, 새 탭 링크 안내, 인쇄 스타일,
  FAQ 등이 꾸준히 다뤄져 반복 감사 대상은 이미 대부분 소진된 상태였다. 코드를 직접
  뒤져 **아직 다뤄지지 않은 새 항목 3가지**를 찾았다:
  1. 12개 페이지에 화면상 breadcrumb(`<nav class="breadcrumb">`)은 있지만, 정작
     `BreadcrumbList` schema.org 구조화 데이터는 전혀 없음을 확인(기존에 추가된
     Article/WebPage/CollectionPage JSON-LD와 별개로 빠져 있던 항목) → 개발팀에 지시.
  2. `assets/css/style.css`에서 `.site-nav a`, `.footer-nav a`, `.region-card`,
     `.filter-pill`, `.map-pin`에는 모두 커스텀 `:focus-visible` 스타일이 있는데,
     `.back-button`(← 뒤로가기)과 `.spot-map-link`(📍 지도에서 보기)만 `:hover`만
     있고 `:focus-visible` 커스텀 스타일이 빠져 있음을 확인 → 디자인팀에 지시.
  3. `support/faq.md`에 광고/제휴 "문의 방법"에 대한 FAQ는 있었지만, "이 사이트에
     지금 광고나 협찬이 있는가"라는 신뢰도 관련 FAQ 자체는 없었음(privacy 페이지의
     AdSense 조항은 가능성 안내일 뿐 현재 상태를 확정하지 않음) → CS팀에 지시.
  - favicon(`data:,`)은 의도된 빈 favicon placeholder로 확인되어 새 이슈로 만들지
    않았다. viewport 메타태그는 전 페이지 정상 존재 확인. 이미지 alt/width-height는
    이미 CSS `aspect-ratio`로 CLS 처리돼 있어(09-22 확인 사항) 재확인만 하고 새
    지시를 만들지 않았다.

**지시 내용**: breadcrumb 내비게이션이 있는 12개 페이지(지역 허브 6곳, 발행 글 3편,

breadcrumb 경로와 정확히 일치하는 `BreadcrumbList` JSON-LD를 추가. 배포 도메인 미확정
상태이므로 기존 Article JSON-LD의 `image` 필드가 상대경로를 쓰는 것과 동일한 관례로
`item`도 상대경로 사용. 다른 것은 일절 건드리지 말 것.

**산출물**: 12개 파일에 각각 `BreadcrumbList` JSON-LD 블록 1개씩 추가(총 246
insertions, 0 deletions). 각 페이지의 실제 breadcrumb 텍스트·href를 정확히 반영,
마지막(현재 페이지) 항목은 관례대로 `item` 필드 생략.

**검수**:
- ✅ **마스터가 12개 파일 전체 `git diff`를 직접 읽음**: 모든 파일이 삽입만 있고
  삭제 없음, 기존 breadcrumb HTML·기존 JSON-LD·다른 로직은 전혀 바뀌지 않았음을 확인.
- ✅ **마스터가 독립적으로 재검증**: Python 스크립트로 12개 파일에서 `BreadcrumbList`
  블록을 각각 정확히 1개씩 추출해 `json.loads`로 파싱 — 전부 유효한 JSON, `position`
  값이 1부터 순차적임을 확인. 각 파일의 `<script>`/`</script>` 태그 개수가 3/3으로
  일치(태그 깨짐 없음)함을 직접 카운트로 확인.
- ✅ 개발팀 자체 보고(Python으로 기존+신규 JSON-LD 블록 파싱, `git diff --stat`)와
  마스터의 독립 검증 결과가 일치함을 확인.
- ✅ 요청 범위를 정확히 수행, 커밋/배포 시도 없음(지시대로 master가 검수 후 커밋).

## 5. 승인 필요 / 보류 항목

- **다음 콘텐츠(가나자와) 본문 작성** — 실제 스팟 리서치(WebSearch)가 필요한 기획팀
  (planner) 영역이라 오늘 지시 대상에서 제외했다(오늘 요청 범위가 CS·디자인·개발
  세 팀이었음).
- **`sitemap.xml`/`robots.txt`, 각 HTML의 `og:url`/`canonical`/`og:image`/
  `twitter:image`, JSON-LD의 `image`/breadcrumb `item` 절대 URL화** — 실제 배포
  도메인이 확정되어야 활성화 가능. 오늘 추가한 `BreadcrumbList`의 `item`도 기존
  Article `image` 필드와 동일하게 상대경로로 두었으며, 도메인 확정 시 함께 절대
  URL로 갱신이 필요하다(기존부터 반복되는 보류 항목에 이번 항목도 포함시킴).
- **"예약 & 이동 정보"(제휴 링크) 미연동** — 실제 제휴 계약·외부 서비스 가입이
  필요한 사안이라 사용자 승인 없이는 진행할 수 없다. 오늘도 변경 없음.
- **우레시노 온천 전용 히어로 이미지 부재** — 기존부터 반복 기록된 이슈. 이미지
  조달은 외부 리소스 조달이 필요해 여전히 사용자 판단/향후 콘텐츠 제작 단계 소관.
- **다크모드 수동 전환 기능, 실제 광고(AdSense) 게재 여부, 협찬 표시 내부 정책** —
  모두 확정된 계획이 없는 상태로, 오늘 CS팀 FAQ에서도 "확인 후 안내"로 정직하게
  남겼다. 실제로 결정되면 사용자 판단이 필요하다.
- **실제 배포(호스팅 연동) 여부**, **광고/제휴 실제 진행 여부·조건**, **실제 방문자
  문의 채널 확인** — 이번 세션 도구로는 확인할 수단이 없어 계속 보류.
- **디자인팀 focus-visible 스타일의 실제 브라우저 렌더링 확인** — 코드 레벨(중괄호
  짝, 변수 정의, 인쇄 스타일과의 충돌 여부)로는 검증했으나, 실제 브라우저에서 Tab
  키로 포커스 이동 시 시각적으로 올바르게 보이는지는 이번 세션에서 확인하지 못했다.
  기존에 이미 검증된 동일 패턴(`--color-accent-2` 아웃라인)을 그대로 복제한 것이라
  위험은 낮다고 판단했지만, 미검증 상태임을 명시한다.
- 오늘 되돌리기 어려운 작업(강제 push, 파일/브랜치 삭제, 실제 메시지 발송, 외부
  서비스 가입/결제 등)은 전혀 수행하지 않았다.
