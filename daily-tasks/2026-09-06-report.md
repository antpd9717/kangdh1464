## 2. 팀별 작업 및 검수 결과

### 개발팀 (developer)
**지시 내용**: 실제 콘텐츠가 채워진 글 3편이 사이트 어디에서도 링크되지 않는 문제를 고치기
위해, 각 글이 속한 지역 허브 페이지(`region/osaka`, `region/setouchi-hokuriku`,
`region/fukuoka`)에 해당 글로 가는 내부 링크를 추가할 것. 기존 클래스 재사용, 범위는 이
3개 파일로 한정.

**산출물**: `region/osaka/index.html`, `region/setouchi-hokuriku/index.html`,
`region/fukuoka/index.html` 각 파일에 "이 지역 심층 가이드" 섹션을 추가하고, 기존
`related-list` 클래스(글 하단 "함께 보면 좋은 글" 영역에서 쓰이던 것)를 그대로 재사용해
해당 글로 가는 링크 1개씩 삽입. 새 CSS 클래스 추가 없음. 총 3개 파일, 21줄 추가.

**검수**:
- ✅ 범위 준수 — 지정된 3개 파일만 수정, 글 본문·다른 지역 허브·`index.html`은 손대지 않음,
  git add/commit/push 하지 않고 마스터에게 위임
- ✅ **자체 검증 근거 있음**: 로컬 서버로 새 링크 대상 3개 + 기존 주요 페이지 10개를 curl로
  전수 확인(모두 200), 각 파일의 `<section>`/`<article>` 태그 짝이 수정 전후로 정확히
  일치함을 확인
- ✅ **마스터가 재확인**: `git diff`로 실제 diff가 보고 내용과 정확히 일치함을 확인, 별도로
  로컬 서버를 다시 띄워 3개 링크의 실제 상대경로(`../../content/...`)가 정확한 대상 파일로
  귀결되고 200 응답함을 직접 재검증. `assets/css/style.css`에 `.related-list` 클래스가
  실제로 정의되어 있어 새 CSS 없이 기존 스타일을 그대로 재사용한다는 주장이 사실임을 확인.

### 디자인팀 (designer)
**지시 내용**: 처음 실제 콘텐츠가 채워진 글 3편의 마크업이 기존 CSS 클래스와 잘 맞는지,
개발팀이 오늘 추가한 "이 지역 심층 가이드" 섹션이 기존 "함께 보면 좋은 글" 영역과 시각적으로
일관되게 렌더링되는지 점검.

**산출물**: `assets/css/style.css`에 규칙 2개 추가 — 글 본문 안의 클래스 없는 `<ul>`(맛집
리스트 등)에 `max-width: 68ch`(문단과 폭 통일)와 항목 간 `margin-top`(간격 확보)을 적용.
`.related-list`/`.article-list`처럼 이미 자체 레이아웃을 가진 목록은 `:not([class])`로
명시적으로 제외해 필터 카드 간격과 중복 적용되지 않게 함. 나머지(글 3편 마크업, 지역 허브
3편, `placeholder-block` 스타일, 다크모드 대비)는 점검 후 문제없음을 확인해 "변경 없음"으로
정직하게 보고.

**검수**:
- ✅ 범위 준수 — 지정된 6개 파일 + `style.css`로 한정, 실제로는 CSS 1개 파일만 수정
- ⚠️ **자체 한계 고지**: 브라우저 렌더링 도구 없이 정적 코드 리뷰(클래스 매칭, CSS 변수,
  미디어쿼리)로만 검증했다고 명시. 실제 대비율 수치, 실측 줄바꿈은 미확인.
- ✅ **마스터가 재확인**: `grep`으로 `.article-list`(스팟 필터 카드, `814행`)와
  `.related-list`가 실제로 클래스를 가진 요소임을 확인, 새 규칙의 `:not([class])` 선택자가
  이 두 클래스를 정확히 제외함을 직접 확인 — 디자인팀이 처음 `:not(.related-list)`만
  쓰려다 `.article-list`(스팟 필터 카드)까지 잘못 건드릴 뻔한 것을 자체적으로 발견해
  `:not([class])`로 고친 경위도 보고서에 정직하게 남김.
- 참고: `privacy/index.html`에도 동일 규칙이 부수효과로 적용됨을 스스로 밝힘 — 범위를
  벗어난 임의 변경이 아니라 선택자 특성상 자연스럽게 적용되는 것이고, 사이트 톤에 오히려
  도움이 되는 방향이라 문제 삼지 않음.

## 4. 승인 필요 / 보류 항목

- **README.md "다음 단계" 절이 낡음** — 여전히 "글 3편의 placeholder 본문을 채운다"고 되어
  있으나 이미 완료된 사실이다. 오늘은 어느 팀에도 배정하지 않았으므로 다음 세션에서 개발팀
  또는 기획팀에 갱신을 지시할 필요가 있다.
- **"예약 & 이동 정보"(제휴 링크) 미연동** — 글 3편 모두 이 섹션이 자리만 마련된 상태다.
  실제 제휴 계약·가입은 외부 서비스 가입/승인이 필요한 사안이라 사용자 승인 없이는 진행할
  수 없다.
- **실제 배포(호스팅 연동) 여부** — `git push origin main`은 완료했으나, 이 저장소가 실제로
  Netlify/Vercel 등과 연동되어 인터넷에 공개되는지는 이번 세션에서도 확인할 수단이 없었다.
- **광고/제휴 실제 진행 여부·조건** — 사용자 판단이 필요한 항목으로 계속 남겨둔다.
- 오늘 되돌리기 어려운 작업(강제 push, 파일/브랜치 삭제, 실제 메시지 발송, 외부 서비스
  가입/결제 등)은 전혀 수행하지 않았다.
