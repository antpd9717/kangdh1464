**지시 내용**: `assets/css/style.css`에 `@media (prefers-reduced-motion: reduce)` 블록을
신규 추가해, 동작 줄이기를 켠 방문자에게 transition/transform 기반 애니메이션(이동·확대)

없이 순수 CSS 추가만.

**산출물**: 파일 맨 끝(기존 코드 무수정, 순수 추가)에 새 미디어쿼리 블록(52줄) 추가.
전역 `transition-duration`/`animation-duration` 등을 사실상 0으로 축소하고, 지도 핀
확대(scale), 지역 카드 hover 이동(translateY)·썸네일 확대·화살표 슬라이드인, 스팟 카드
hover 이동, 관련 글 링크 hover 이동을 각각 `transform: none`으로 개별 override.

**검수**:
- ✅ **마스터가 diff 전체를 직접 읽음**: 기존 코드 라인은 전혀 바뀌지 않고 파일 끝에
  새 블록만 추가됐음을 확인(`+52줄`, 삭제 0줄).
- ✅ **마스터가 별도로 브레이스 짝(153개 open/153개 close)을 세어 구문 오류 없음을
  확인**했고, 디자인팀이 보고한 selector들이 실제 파일의 hover 규칙과 정확히 일치하는지
  각각 대조했다.
- ✅ **잠재적 함정을 마스터가 직접 검증**: `.region-card::after`의 기본 상태에
  `transform: translateX(-4px)`가 있어, hover/focus뿐 아니라 기본 상태의 `::after`에도
  `transform: none`을 적용했는지 확인 — 세 selector(`.region-card::after`,
  `:hover::after`, `:focus-visible::after`) 모두에 적용되어 있어 화살표가 어느 상태에서도
  밀려나 있지 않고 opacity 페이드만 남는 것을 확인, 의도대로 올바름.
- ✅ hover 대상 selector들이 base(비-hover) 상태의 transform을 건드리지 않아 정적
  레이아웃에는 영향이 없음을 확인(`.map-pin-circle`, `.region-card`, `.spot-card`,
  `.related-list a` 각각의 기본 규칙에 transform이 없음을 grep으로 재확인).
- ⚠️ **검증되지 않음**: 실제 브라우저 렌더링, OS "동작 줄이기" 설정을 켠 상태의 시각적
  확인, 다크모드+reduced-motion 동시 적용 시의 실제 렌더링 — 디자인팀도 마스터도 이번
  세션 도구로는 확인 불가.
