## 5. 승인 필요 / 보류 항목

- **다음 콘텐츠(가나자와) 본문 작성** — 실제 스팟 리서치(WebSearch)가 필요한 기획팀
  (planner) 영역이라 오늘도 진행하지 않았다.
- **`sitemap.xml`/`robots.txt`, 각 HTML의 `og:url`/`canonical`/`og:image`/
  `twitter:image`의 `https://example.com` 플레이스홀더 도메인** — 실제 배포 도메인이
  확정되어야 활성화 가능. 오늘도 사용자 판단 대기.
- **"예약 & 이동 정보"(제휴 링크) 미연동** — 실제 제휴 계약·외부 서비스 가입이 필요한
  사안이라 사용자 승인 없이는 진행할 수 없다.
- **실제 배포(호스팅 연동) 여부 및 신설 `404.html`의 실제 동작** — `git push origin main`은
  완료했고 로컬 렌더링(아래 검증 내역)은 문제없음을 확인했으나, 이 저장소가 실제로
  Netlify 등과 연동돼 있는지, 배포 후 존재하지 않는 URL에 실제로 새 404 페이지가 뜨는지는
  이번 세션 도구로는 확인할 수단이 없었다.
- **광고/제휴 실제 진행 여부·조건** — 사용자 판단이 필요한 항목으로 계속 남겨둔다.
- 오늘 되돌리기 어려운 작업(강제 push, 파일/브랜치 삭제, 실제 메시지 발송, 외부 서비스
  가입/결제 등)은 전혀 수행하지 않았다. 세션 시작 시 로컬 `main`이 최신 커밋보다
  뒤처져 있던 것도 fast-forward 병합(비파괴적)으로만 정리했다.

## 6. 참고 — 검증됨 vs 검증되지 않음 요약

- **실측으로 검증됨**: 세션 시작 시 origin/main이 최신 상태였음(fetch로 확인); 신설된
  `404.html`이 참조하는 12개 경로가 모두 실존함; `404.html`의 head 구조가 `about/
  index.html`과 의도된 차이(noindex 추가, og 태그 미포함)를 제외하면 일치함; 디자인팀이
  재사용했다고 주장한 `related-list` 클래스가 실제로 3개 지역 허브 파일에서 이미 쓰이고
  있음(grep으로 확인); `404.html`/`contact`/`privacy` 3개 페이지가 모바일·데스크톱 모두
  콘솔 에러·네트워크 실패 없이(세션 프록시발 폰트 에러 제외) 정상 렌더링되고 레이아웃도
  자연스러움을 master가 직접 헤드리스 브라우저 스크린샷으로 확인함; 세 팀 모두 각자
  보고한 파일만 정확히 변경했음(`git diff --stat`으로 확인); CS팀 FAQ 대조 결과 내용
  불일치가 없었고 날짜 표기 갱신 3곳이 diff와 정확히 일치함.
- **검증되지 않음(정직하게 미확인으로 남김)**: 실제 인터넷 공개 여부/배포 도메인; 실제
  Netlify 환경에서 신설 `404.html`이 자동으로 쓰이는지(로컬 렌더링은 확인했으나 Netlify의
  자동 인식 동작 자체는 배포 후에만 확인 가능); 실제 방문자 문의 채널 확인(이 세션
  도구로는 접근 불가 — 기존 상태 유지만 함).
